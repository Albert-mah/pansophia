# skill:chapter — 章节收尾审计

一个章节的卡和题都齐了之后,收尾检查 + 汇报。**不产出新内容**,只找缺口;
发现缺口回到对应上游 skill 修,修完重跑本审计。

> 章节的「汇总」不是再写一张汇总卡:考点状态地图(课程页目录)、整课混合练、
> 模拟试卷都是前端现成的,题库和卡片齐了它们自动成立。

## 审计清单(逐项跑,逐项记 ✓/✗)

1. **覆盖**:该 topic 每个考点都有卡片或讲解页?
   `node tools/validate.js` 全绿 + 人工对一遍该章节 points 清单。
2. **配题**:`python3 tools/import_questions.py --coverage` 退出码 0
   (每张 drill 卡 ≥3 题)。
3. **模拟卷成立**:每个 drill 考点至少 1 个变体组(模拟卷抽变体防背题)。
   逐 kp `curl -s --get --data-urlencode "kp=<kp>" http://127.0.0.1:8790/api/questions`
   看 `variant_of` 字段是否有非空的。
4. **一致性**(抽查本章 3 张卡):
   - 卡片之间没有互相矛盾的表述(同一术语同一叫法);
   - example 算出来的结果是对的、题目答案是对的(逐题验算/验证);
   - pitfall 和题目错误选项对得上。
5. **learn/task 卡合理性**:learn 卡真的不适合出题吗?task 卡的完成标准清晰吗?

## 一门课「补上」的判定(与 docs/ai-tutor-skill.md §5 一致)

课本到位 + 全部考点有卡/讲解 + drill 全配题 + 用户最终试卷校验通过。
前三项本审计负责,最后一项是用户在 practice 屏「模拟试卷」自己考出来的。

## 产出汇报

章节名、5 项清单结果、发现的缺口清单(缺口→该回哪个 skill 修)、验算发现的内容错误。
